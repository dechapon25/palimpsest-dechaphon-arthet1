  <action>
**Step 1 — Verify Docker is installed on Oracle VM:**
```
ssh user@oracle-ip docker --version
```
If Docker is not installed:
```
ssh user@oracle-ip 'curl -fsSL https://get.docker.com | sh && sudo usermod -aG docker $USER'
```
Then reconnect (group membership requires new session).

**Step 2 — Transfer the image to Oracle VM (no Docker Hub required, per RESEARCH.md):**
```
docker save palimpsest | gzip | ssh user@oracle-ip 'gunzip | docker load'
```
This pipes the image directly via SSH. Replace `user@oracle-ip` with the actual SSH connection string. Expect transfer to take 2-5 minutes depending on connection speed.

Verify image arrived on Oracle VM:
```
ssh user@oracle-ip 'docker images palimpsest'
```
Expected: palimpsest image listed with the correct tag.

**Step 3 — Configure OS-level firewall on Oracle VM (firewalld, Oracle Linux 8 assumption per RESEARCH.md A1):**
```
ssh user@oracle-ip 'sudo firewall-cmd --zone=public --permanent --add-port=7860/tcp && sudo firewall-cmd --reload'
ssh user@oracle-ip 'sudo firewall-cmd --list-ports'
```
Expected output of list-ports: includes `7860/tcp`

If the OS is Ubuntu/Debian instead of Oracle Linux (different from RESEARCH.md A1 assumption):
```
ssh user@oracle-ip 'sudo ufw allow 7860/tcp && sudo ufw status'
```

**Step 4 — Deploy the container on Oracle VM (per D-02):**
```
ssh user@oracle-ip 'docker run -d --restart=always \
  -p 7860:7860 \
  -e GOOGLE_API_KEY=<your-actual-key> \
  --name palimpsest-prod \
  palimpsest'
```
Replace `<your-actual-key>` with the actual Google AI Studio API key. This runs with restart=always so it survives reboots (D-02). No memory/CPU limits per D-08 (Oracle VM has 24 GB / 4 vCPU).

**Step 5 — Verify container is running on Oracle VM:**
```
ssh user@oracle-ip 'docker ps | grep palimpsest-prod'
```
Expected: container listed with status "Up X seconds"

```
ssh user@oracle-ip 'curl -s -o /dev/null -w "%{http_code}" http://localhost:7860/'
```
Expected: 200

**Step 6 — Check FastMCP stdio subprocess:**
```
ssh user@oracle-ip 'docker logs palimpsest-prod 2>&1 | tail -20'
```
Look for Gradio startup message. No error about MCP subprocess at startup is expected (it starts on first use).

Note: The OCI Console security list is a separate firewall layer that requires browser action — handled in Task 2.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → Oracle VM port 7860 | Gradio accepts file uploads from any source; file validation from Phase 3 intake layer applies |
| Oracle VM OS → Docker container | Container runs as root; host network isolation via Docker bridge |
| Container → Wikidata/Wikipedia HTTPS | MCP subprocess makes external calls; Oracle VM egress should be unrestricted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-D-01 | Information Disclosure | GOOGLE_API_KEY in docker run command | high | mitigate | Do not paste docker run command with key in shell history. Use: `read -s GOOGLE_API_KEY && docker run ... -e GOOGLE_API_KEY=$GOOGLE_API_KEY palimpsest`. Alternatively, pass via --env-file (requires .env on VM, not checked in). |
| T-04-D-02 | Denial of Service | Public Gradio endpoint (unrestricted access) | medium | accept | Competition submission, short-lived deployment. Rate limiting not required for Kaggle judge access period. Gradio has no built-in auth for this version. |
| T-04-D-03 | Information Disclosure | Wikidata/Wikipedia external calls from container | low | accept | Informational calls only (entity lookup, date normalization). No PII is sent. Data returned is public domain. |
