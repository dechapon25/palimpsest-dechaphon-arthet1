**Dockerfile** (use python:3.11-slim per D-05):

Layer ordering (requirements before source — cache deps layer across source changes):
1. FROM python:3.11-slim
2. WORKDIR /app
3. COPY requirements.txt .
4. RUN pip install --no-cache-dir -r requirements.txt
5. COPY src/ ./src/
6. COPY data/samples/ ./data/samples/

Environment variables (all three are required):
- ENV PYTHONPATH=/app/src — resolves missing pyproject.toml [project] section; makes `python -m palimpsest.app` work (RESEARCH.md Finding 2 / Pitfall 1)
- ENV GRADIO_SERVER_NAME=0.0.0.0 — Gradio reads this natively and overrides its default loopback binding; without this the UI is unreachable outside the container (RESEARCH.md Pitfall 4)
- ENV PYTHONUNBUFFERED=1 — prevents stdout buffering that corrupts the FastMCP stdio JSON-RPC channel (RESEARCH.md Pitfall 2)

Then: EXPOSE 7860

CMD: ["python", "-m", "palimpsest.app"]

**IMPORTANT:** API credentials must not be set in any Dockerfile ENV instruction. Secrets are injected exclusively at container runtime via `docker run -e`. Never bake credentials into the image.

**Discretion (HEALTHCHECK):** Optionally add a HEALTHCHECK using curl. If adding it, install curl in a combined apt-get layer before CMD:
  RUN apt-get update && apt-get install -y --no-install-recommends curl && rm -rf /var/lib/apt/lists/*
  HEALTHCHECK --interval=30s --timeout=10s --start-period=90s --retries=3 CMD curl -f http://localhost:7860/ || exit 1
The 90s start-period accounts for Gradio startup time.

**Step 1 — Fix app.py (per D-06 and RESEARCH.md Finding 3 / PATTERNS.md app.py section):**

The current `demo.launch()` call at line 328 uses only `theme=gr.themes.Soft()`. Gradio defaults to binding on 127.0.0.1 (loopback), which is unreachable outside a Docker container even with -p port mapping.

Replace the current `demo.launch(theme=gr.themes.Soft())` call with:

```python
demo.launch(
    theme=gr.themes.Soft(),
    server_name="0.0.0.0",
    server_port=int(os.environ.get("PORT", 7860)),
)
```

Add an explanatory comment on the line immediately above the server_name argument explaining that the 0.0.0.0 binding is required for Docker (default loopback is not reachable outside container even with port mapping).

Note: `import os` is already present in app.py (check lines 1-45 to confirm; do NOT add a duplicate import).

The Dockerfile also sets GRADIO_SERVER_NAME=0.0.0.0 as belt-and-suspenders (Gradio reads it natively), but the explicit server_name argument in code is preferred per PATTERNS.md guidance and makes the configuration visible in source.

**Step 2 — Build the container image:**

From the repository root, run:
```
docker build -t palimpsest .
```

If build fails: check error output. Common causes: requirements.txt not found (wrong WORKDIR), pip install error (network), COPY path mismatch.

**Step 3 — Smoke test the container locally:**

Run the container on a non-conflicting port (7861 to avoid collision with any running local dev server):
```
docker run --rm -d --name palimpsest_smoke -e GOOGLE_API_KEY=smoke_test -p 7861:7860 palimpsest
```

Wait 10 seconds for Gradio startup, then verify Gradio loads:
```
sleep 10 && curl -s -o /dev/null -w "%{http_code}" http://localhost:7861/
```
Expected: 200

Check that Gradio bound to 0.0.0.0 (not loopback):
```
docker logs palimpsest_smoke 2>&1 | grep "Running on"
```
Expected: contains "0.0.0.0:7860" (not "127.0.0.1:7860")

Stop the smoke test container:
```
docker stop palimpsest_smoke
```

**Step 4 — Verify no credentials in image layers:**

The output should show exactly the three ENV vars set in Dockerfile (PYTHONPATH, GRADIO_SERVER_NAME, PYTHONUNBUFFERED) and nothing else. No credential values should appear.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host filesystem → Docker build context | Files sent to Docker daemon; must not include .env |
| Docker image layers → runtime | Baked ENV values persist in all derived images; credentials must not be baked in |
| Container egress → Wikidata/Wikipedia | FastMCP subprocess makes HTTPS calls; no OCI egress restriction expected |
| External network → container port 7860 | Gradio accepts file uploads from any source; already validated by Phase 3 intake layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information Disclosure | Dockerfile ENV instruction | high | mitigate | Never set credential values in Dockerfile ENV. Inject at runtime only via `docker run -e`. Verify with `docker inspect` after build: ENV layer should contain exactly PYTHONPATH, GRADIO_SERVER_NAME, PYTHONUNBUFFERED — no credential names or values. |
| T-04-02 | Information Disclosure | Docker build context (.env in context) | high | mitigate | .dockerignore must list `.env` and `.env.*`. If .env is in build context, `docker history` can expose it even without COPY. Verify with `docker build --no-cache` from clean clone after adding .dockerignore. |
| T-04-03 | Information Disclosure | API key exposure in container logs | high | mitigate | app.py and run.py must not log the value of GOOGLE_API_KEY. Verify with `docker logs` after smoke test — key value `smoke_test` should not appear in log output. |
| T-04-04 | Elevation of Privilege | Container running as root | medium | accept | Python:3.11-slim runs as root by default. For a competition submission with no multi-tenancy, this is acceptable. Adding `USER 1001` is discretionary (noted in CONTEXT.md Claude's Discretion). |
| T-04-05 | Tampering | PYTHONPATH traversal | low | accept | PYTHONPATH is set to static /app/src in Dockerfile. No user-controlled input reaches PYTHONPATH. Risk is negligible. |
| T-04-06 | Information Disclosure | Gradio share=True | low | accept | share=False is Gradio's default. CMD does not set share=True. Verify: `grep 'share=True' src/palimpsest/app.py` returns empty. |
</threat_model>
