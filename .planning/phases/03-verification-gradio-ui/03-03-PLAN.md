<objective>
Gap-closure plan addressing the two BLOCKER findings from 03-VERIFICATION.md. Both fixes are surgical single-line additions; no logic is restructured.

CR-03 (Task 1): verification.py GenerateContentConfig omits max_output_tokens=65536, violating the explicit CLAUDE.md constraint "Set maxOutputTokens=65536 explicitly or transcription silently truncates." For a long manuscript the confidence_map word-score array can exceed the model's default output token limit, causing silent mid-array truncation that produces malformed JSON and feeds directly into CR-02.

CR-02 (Task 2): The four json.loads() calls in transcribe_manuscript() (app.py lines 185-199) have no exception handling. The orchestrator marks status="ok" when individual pipeline agents fail (their errors land in errors[]), so the status gate passes even when the output JSON is malformed. Any resulting JSONDecodeError or TypeError propagates as an unhandled Python exception — Gradio shows a generic 500 page instead of the gr.Error banner required by D-11.

Fix order: CR-03 first (reduces the probability of malformed JSON entering the parse calls) then CR-02 (catches any remaining parse failures).

Purpose: Closes the two blockers that prevent full phase 03 verification sign-off.
Output: Patched verification.py and app.py; both files remain importable and all existing smoke tests continue to pass.
</objective>
