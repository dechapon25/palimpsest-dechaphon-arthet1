# Phase 2 -- UI Design Contract

> Visual and interaction contract for Phase 2: Full Multi-Agent System.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase 2 is a backend phase.** It produces no visual interface. This contract
> specifies the **output data schemas** and **display conventions** that Phase 3's
> Gradio UI will consume. Locking these now prevents rework when the Gradio
> interface is built.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Python backend phase) |
| Preset | not applicable |
| Component library | Gradio (Phase 3 -- output schemas locked here) |
| Icon library | not applicable |
| Font | Gradio default (system font stack) |

**Rationale:** Phase 2 has no visual interface (requirements CLN-01 through CTX-03 are
all backend pipeline work). The "UI hint: yes" on the roadmap indicates Phase 2 outputs
feed Phase 3's Gradio UI. This contract locks the data shapes and display conventions
so Phase 3 can render them without schema negotiation.

## Typography

Not applicable for Phase 2 (no visual interface). The following conventions apply
to **text content produced by Phase 2 agents** that Phase 3 will render:

| Role | Convention | Source |
|------|------------|--------|
| Cleaned transcription body | Plain text, UTF-8, no HTML markup | D-04 |
| Uncertainty marker | Suffix `[?]` appended to ambiguous words | D-06 |
| Historical notes entity names | Plain text, case-preserved from source | D-08 |
| Change log entries | `{original}` -> `{expanded}` format in changes array | D-04 |

## Color

Not applicable for Phase 2 (no visual interface). The following semantic color
assignments are declared for Phase 3 consumption:

| Role | Semantic Meaning | Phase 3 Mapping |
|------|------------------|-----------------|
| Uncertainty marker `[?]` | Low confidence expansion | Amber/yellow highlight in Gradio UI |
| Successful entity resolution | Entity matched in Wikidata | Default text (no special color) |
| Failed entity resolution | Entity not found / query failed | Gray text or "not found" label |
| Pipeline error | Agent failure with error message | Red/destructive in error display |

Accent reserved for: uncertainty markers (`[?]` words) and entity resolution status indicators only.

## Output Data Contracts

These JSON schemas are the **canonical interface** between Phase 2 agents and
Phase 3's Gradio UI. Phase 2 agents MUST produce output conforming to these
schemas. Phase 3 UI components MUST consume these schemas without transformation.

### Cleaning Agent Output (D-04)

Written to session state key: `"cleaned_transcription"`

```json
{
  "cleaned_text": "string -- full cleaned transcription text, UTF-8",
  "changes": [
    {
      "original": "string -- original token from raw transcription",
      "expanded": "string -- expanded/normalized form",
      "reason": "string -- why this expansion was applied"
    }
  ]
}
```

**Display rules for Phase 3:**
- `cleaned_text` renders in the main transcription panel (UI-02)
- `changes` array populates the raw/clean toggle diff view (UI-05)
- Words ending in `[?]` in `cleaned_text` are uncertain expansions (D-06)
  and receive amber highlight treatment (UI-03, VER-02)

### Context Agent Output (D-08)

Written to session state key: `"context_notes"`

```json
[
  {
    "entity": "string -- entity name as found in text",
    "type": "string -- person | place | date | organization",
    "wikidata_id": "string | null -- Qxxxxx ID or null if not found",
    "description": "string -- one-sentence description from Wikidata/Wikipedia",
    "dates": "string | null -- relevant dates (birth-death, founding, etc.)",
    "source_url": "string -- Wikidata or Wikipedia URL for attribution"
  }
]
```

**Display rules for Phase 3:**
- Each entity renders as a card/row in the historical notes panel (UI-04)
- `entity` is the heading; `description` is the body text
- `dates` displays inline after the entity name when present
- `source_url` renders as a clickable attribution link
- Entities with `wikidata_id: null` display a "not found" indicator

### Extended Pipeline Output (D-11 extension)

The D-11 output dict from Phase 1 gains two new metadata fields.
Top-level keys remain frozen per D-11.

```json
{
  "status": "ok | error | partial",
  "raw_transcription": "string | null",
  "metadata": {
    "filename": "string",
    "model": "gemini-2.5-pro",
    "tokens_used": "number | null",
    "cleaning_model": "gemini-2.5-flash",
    "entities_found": "number",
    "entities_resolved": "number"
  },
  "errors": ["string"]
}
```

### MCP Tool Response Schemas

Each FastMCP tool returns a JSON object. These schemas define what the
context agent receives and what Phase 3 may display in debug/detail views.

**`lookup_entity(name: str)`** returns:
```json
{
  "found": "boolean",
  "entity": "string",
  "wikidata_id": "string | null",
  "description": "string",
  "dates": "string | null",
  "source_url": "string"
}
```

**`normalize_date(text: str)`** returns:
```json
{
  "original": "string",
  "iso_date": "string | null -- ISO 8601 format",
  "explanation": "string"
}
```

**`expand_abbreviation(token: str)`** returns:
```json
{
  "abbreviation": "string",
  "expansion": "string | null",
  "confidence": "string -- high | medium | low",
  "source": "string -- wikidata | dictionary | inference"
}
```

**`place_context(place: str, year: int)`** returns:
```json
{
  "place": "string",
  "year": "number",
  "historical_name": "string | null",
  "modern_name": "string | null",
  "description": "string",
  "wikidata_id": "string | null",
  "source_url": "string"
}
```

## Copywriting Contract

These copy strings apply to Phase 2 pipeline output messages consumed by
the CLI runner (Phase 1) and later by Gradio (Phase 3).

| Element | Copy |
|---------|------|
| Primary CTA | not applicable (backend phase -- no user-facing buttons) |
| Processing status: cleaning | "Cleaning and normalizing transcription..." |
| Processing status: context | "Enriching named entities with historical context..." |
| Empty state: no entities found | "No named entities detected in the transcription." |
| Empty state: cleaning no changes | "No abbreviations or archaic spellings detected. Text passed through unchanged." |
| Error: cleaning agent failure | "Cleaning failed: {error_message}. Raw transcription is still available." |
| Error: MCP server unreachable | "Historical context unavailable: could not reach Wikidata. Cleaned text is still available." |
| Error: entity lookup failed | "Could not resolve entity '{entity_name}': {reason}." |
| Partial: some entities resolved | "{resolved_count} of {total_count} entities resolved. Unresolved entities marked." |
| Uncertainty marker explanation | "Words marked with [?] have uncertain expansions. The original abbreviation could not be unambiguously resolved." |

## Interaction States

Phase 2 pipeline states that Phase 3 Gradio UI must handle:

| State | Condition | User Sees (Phase 3) |
|-------|-----------|---------------------|
| Pipeline success | All agents complete, entities resolved | Clean text + notes panel + changes list |
| Cleaning pass-through | No abbreviations found | Clean text identical to raw, empty changes array |
| Partial entity resolution | Some entities found in Wikidata, some not | Notes panel with resolved entries; unresolved marked |
| No entities found | Context agent finds zero named entities | Notes panel with "No named entities detected" message |
| Cleaning error | Cleaning agent fails | Raw transcription shown, cleaning section shows error |
| MCP error | Wikidata/Wikipedia unreachable | Clean text shown, notes panel shows connectivity error |
| Full pipeline error | Orchestrator catches exception | Error message with descriptive context (ORC-02) |
