<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → security intake | User-supplied file path is the attack surface; any file content could be malicious |
| security intake → Pillow | Raw bytes cross into a parsing library before EXIF strip; magic-byte check must precede Pillow.open() |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `security/intake.py` — file type check | mitigate | Use `filetype.guess()` (magic bytes) — never trust file extension; JPEG has 3 magic-byte variants, all handled by the library |
| T-01-02 | Denial of Service | `security/intake.py` — file size | mitigate | Check `stat().st_size` before reading any bytes; reject files > 20 MB immediately |
| T-01-03 | Information Disclosure | `security/intake.py` — EXIF metadata | mitigate | Reconstruct via `Image.new()` + `putdata()` — no metadata carried over; `ImageOps.exif_transpose()` applies orientation then discards EXIF |
| T-01-04 | Elevation of Privilege | `agents/transcription.py` — prompt injection via document content | mitigate | Barrier 1: `response_mime_type="application/json"` forces structured output (Plan 02). Barrier 2: system prompt explicitly labels document content as data (Plan 02). See D-18. |
| T-01-05 | Information Disclosure | `.env` / `GOOGLE_API_KEY` | mitigate | `python-dotenv` loads from `.env`; `.gitignore` excludes `.env`; `.env.example` documents variable names only without values |
| T-01-06 | Tampering | npm/pip/cargo installs (package legitimacy) | mitigate | Package Legitimacy Audit in RESEARCH.md: all 5 production packages manually verified against official source repos; no SLOP verdicts; slopcheck complete |
</threat_model>
