Four fixes, no restyling:

1. Stuck processing card (main bug). The submit chain is
   `submit_btn.click(fn=show_processing, ...).then(fn=transcribe_manuscript, outputs=outputs_full)`.
   When `transcribe_manuscript` raises `gr.Error`, Gradio applies NO outputs, so
   `processing_section` (index 10) stays visible with the spinner running forever.
   Fix: append one more chained step at the end of the submit chain:
   `.then(fn=hide_processing, inputs=[], outputs=[processing_section])`
   where `hide_processing` is a new tiny function next to `show_processing` that returns
   `gr.update(visible=False)` with a docstring noting it runs unconditionally after
   transcribe_manuscript (`.then` fires regardless of success/failure in Gradio,
   unlike `.success`) so the spinner is cleared even when `gr.Error` is raised.
   On success this is a harmless second hide (index 10 already returns hidden).
   Keep all existing `raise gr.Error(...)` calls exactly as they are.

2. Gradio 6 deprecation. Remove the CSS keyword argument from the `gr.Blocks(...)`
   constructor (keep `title=` there — still a valid Blocks parameter) and pass
   `css=CUSTOM_CSS` to `demo.launch(...)` in the `__main__` block instead, alongside
   the existing theme/server_name/server_port arguments. Verified: launch() accepts
   `css` in gradio 6.19.0.

3. Unused imports. Delete the module-level `asyncio` and `sys` import lines (both
   unused since the handler became async in WR-02).
